# USECASE (Cockburn)

## 0. 이 문서의 형식

유스케이스마다 12행 표, 기본 흐름, 확장을 둔다. 확장 번호는 기본 흐름의 단계 번호에 글자를 붙인다(`3a.`).

ID의 글자는 주 액터의 종류를 뜻한다.

| 글자 | 주 액터 | 이 문서 |
|---|---|---|
| `H` | 사람 | UC-H1 ~ UC-H5 |
| `A` | 에이전트 | 없음 |
| `G` | 외부 시스템 | 없음 |
| `S` | 시스템. 하위기능이며 호출자가 있다 | UC-S1 ~ UC-S12 |

**A를 쓰지 않는 이유.** 이 제품의 AI 에이전트는 사용자 목표를 스스로 시작하지 않는다. [[IMBC-PRD-001#R3]]의 적재 시점 에이전트는 LLM이지만, 운영 담당자가 [[#UC-H5]]로 적재를 시작할 때 그 안에서 불리는 [[#UC-S10]]의 수행자다. [[IMBC-PRD-001#G2]]에 따라 에이전트는 화면 뒤에서 리포트의 재료를 만드는 엔진이므로 시스템 경계 안에 있고, 하위기능을 수행하는 주체로만 등장한다. 리포트 발급 경로에는 LLM이 없고, 에이전트가 남긴 산출물과 실행 기록을 조회만 한다([[IMBC-PRD-001#R9]]).

**G를 쓰지 않는 이유.** 상가(상권)정보 API, 지원사업 공고 API, OpenAI API, 창업비용 통계 원천, 앵커 원장은 호출당할 뿐 먼저 유스케이스를 시작하지 않는다. 데이터 적재도 운영 담당자가 [[#UC-H5]]로 시작한다. 분기마다 스냅샷을 자동 갱신하는 스케줄러를 두면 G가 생기지만, 갱신 주기가 [[IMBC-PRD-001]] 미결사항에 남아 있어 두지 않았다.

**시나리오와의 관계.** [[IMBC-SCN-001#S4]](현장 시연)는 별도 유스케이스로 세우지 않았다. 시연자는 네트워크 없는 환경에서 예비창업자 역할을 대신 수행하는 것이므로 [[#UC-H1]]의 확장 1b로 흡수했다. [[IMBC-SCN-001#S6]](데이터 적재와 적재 릴리스 활성화)는 [[#UC-H5]]로 세웠다. [[IMBC-SCN-001#S5]](지역 전환)도 대상 시도의 에이전트 적재가 필요하므로 [[#UC-H4]] 안에서 [[#UC-H5]]를 거친다.

## 2. 사용자 목표 수준 유스케이스

#### UC-H1 창업 계획을 평가받는다

| 항목 | 내용 |
|---|---|
| 범위 | 창업 신용 리포트 엔진 |
| 수준 | 사용자 목표 |
| 주 액터 | 예비창업자 |
| 이해관계자와 관심사 | **예비창업자**: 자기 계획이 살아남을 가능성과 개선 방법을 알고, 그 결과로 은행 평가를 받고 싶다.<br>**심사역**: 넘어오는 리포트의 근거가 추적 가능하고 발급 뒤 고쳐지지 않았기를 바란다.<br>**iM뱅크**: 사업 이력 없는 고객을 놓치지 않으면서 부실 위험은 가려내고 싶다. |
| 사전조건 | 대상 지역의 스냅샷, 창업비용 기준표, 공고 목록과 구조화 조건, 에이전트 산출물을 담은 적재 릴리스가 활성화돼 있다([[#UC-H5]]). |
| 최소 보장 | 평가가 실패해도 근거가 부족한 수치를 담은 리포트는 발급되지 않는다. 입력한 조건은 남아 다시 시도할 수 있다. 입력한 값은 외부 AI로 전송되지 않는다. |
| 성공 보장 | 식별번호가 붙은 리포트가 발급된다. 생존 전망이 업종 기준선·경쟁 밀도 보정·지역 보정으로 분해돼 있고, 두 시점 생존곡선·예산의 평가 대상 시도 동종 창업비용 분포 위치·개선 시나리오·지원사업 판정·기준일·한계 고지가 담긴다. 에이전트가 서술한 대안에는 펼쳐볼 수 있는 실행 기록이 붙는다. |
| 트리거 | 예비창업자가 창업 계획의 평가를 요청한다. |
| 패키지 | 평가 |
| 포함(include) | [[#UC-S1]], [[#UC-S2]], [[#UC-S5]], [[#UC-S3]], [[#UC-S11]] |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 예비창업자가 업종 대·중·소분류, 구·군과 행정동, 예산, 면적을 선택형 입력으로 고르고, 원하면 출생연도를 입력한다. 자유 텍스트 입력란은 없다. 업종·지역은 코호트 매칭에 쓰고 지원사업 조건 대조에도 다시 쓴다. 예산·면적은 창업비용 기준표 대조에, 출생연도는 지원사업 자격 판정에 쓰인다.
2. 예비창업자가 평가를 요청한다.
3. 시스템이 업종·지역에 맞는 코호트의 생존을 집계한다([[#UC-S1]]). 예산·면적·출생연도는 이 집계에 쓰지 않는다.
4. 시스템이 활성 적재 릴리스에서 예산 안에서 생존 전망을 올리는 개선 시나리오를 가져온다([[#UC-S2]]). 입력 조합이 시연 범위 안이면 적재 시점 에이전트가 미리 순위를 매기고 서술해 둔 후보를 조회해 예산으로 거른다. 이 단계에서 LLM을 부르지 않는다.
5. 시스템이 지원사업 공고와 입력 조건을 대조해 자격을 판정한다([[#UC-S5]]).
6. 시스템이 결과를 리포트로 조립해 발급한다([[#UC-S3]]).
7. 예비창업자가 생존 전망의 분해, 15개월·39개월 생존곡선, 예산이 평가 대상 시도 동종 창업비용 분포에서 어디쯤인지(판정 문구 없이 출처·기준연도와 함께), 개선 시나리오와 후보 위치(임대 매물이 아니라는 고지 포함), 업종 변경 대안의 예산 판단 근거, 지원사업 판정, 기준일과 한계 고지를 확인한다.
8. 예비창업자가 대안 옆의 에이전트 실행 기록을 펼쳐 도구 호출 순서·참조 경로·검증 결과를 본다([[#UC-S11]]).
9. 예비창업자가 리포트를 대출 상담 신청에 첨부한다. 리포트가 심사 큐에 들어간다.

**확장**
- **1a. 군위군을 고른다**
  - 1a1. 시스템이 [[#UC-S1]]의 확장 1c에 따라 편입 이전 이력이 없음을 고지하고 분리 집계한다.
- **1b. 외부 네트워크가 없다 (현장 시연·폐쇄망)**
  - 1b1. 3·4는 원래부터 로컬 스냅샷과 로컬에 적재된 에이전트 산출물·창업비용 기준표만 쓰므로 흐름이 달라지지 않는다.
  - 1b2. 5도 원래부터 적재 릴리스의 공고 목록과 구조화 조건을 쓰므로 흐름이 달라지지 않는다. 판정 결과에는 목록을 적재한 시점이 표시된다([[#UC-S5]] 확장 1a).
  - 1b3. 6의 앵커링은 로컬 원장에 기록한다.
  - 1b4. 8의 실행 기록도 로컬에서 펼친다([[#UC-S11]]).
- **1c. 출생연도를 입력하지 않는다**
  - 1c1. 시스템이 평가를 그대로 진행한다. 3·4의 결과는 달라지지 않는다.
  - 1c2. 5에서 연령 조건이 있는 공고는 판정 불가로 분류된다([[#UC-S5]] 확장 3a).
- **3a. 3~6이 10초를 넘긴다**
  - 3a1. 시스템이 지금 수행 중인 단계를 화면에 표시한다.
- **3b. 코호트 집계가 실패한다 (상위 분류로 올려도 표본 부족)**
  - 3b1. 시스템이 리포트를 발급하지 않고, 이 조건으로는 비교할 표본이 부족하다고 알린다. 유스케이스 종료.
- **4a. 예산 안에서 나은 대안이 2개 미만이다**
  - 4a1. 시스템이 찾은 만큼만 리포트에 담고 그 사실을 표시한다([[#UC-S2]] 확장 4a).
- **4b. 입력 조합이 시연 범위 밖이다**
  - 4b1. 시스템이 에이전트 서술 없이 결정론 도구의 상위 대안을 담고, 에이전트 해석이 없다는 사실을 표시한다([[#UC-S2]] 확장 1a).
  - 4b2. 8에서 실행 기록이 없다는 표시가 나온다([[#UC-S11]] 확장 1a).
- **4c. 바꿀 업종에 창업비용 기준값이 없다**
  - 4c1. 시스템이 그 업종으로 바꾸는 대안을 리포트에 담지 않는다([[#UC-S2]] 3).
  - 4c2. 그 결과 대안이 2개 미만이면 4a로 간다.
- **4d. 활성 적재 릴리스가 에이전트가 서술만 맡은 릴리스다**
  - 4d1. 시스템이 대안을 결정론 순위대로 담고, 에이전트는 서술만 맡았다는 표시를 붙인다([[#UC-S2]] 확장 2a).
  - 4d2. 8에서 실행 기록에도 에이전트가 서술만 맡았다는 표시가 나온다([[#UC-S11]] 확장 4a).
- **7a. 조건을 바꿔 다시 평가한다**
  - 7a1. 예비창업자가 1로 돌아간다.
  - 7a2. 시스템이 이전 리포트를 지우지 않고 남겨 두 리포트를 나란히 비교할 수 있게 한다.
- **9a. 첨부하지 않고 끝낸다**
  - 9a1. 리포트는 식별번호로 남아 이후 창구에서 불러올 수 있다([[#UC-H2]] 확장 1a).

**기본 흐름**
1. 창구 직원이 고객의 업종·지역·예산·면적을 선택형 입력으로 고르고, 고객이 원하면 출생연도를 입력한다.
2. 시스템이 코호트 생존을 집계하고([[#UC-S1]]) 활성 적재 릴리스에서 개선 시나리오를 가져오고([[#UC-S2]]) 지원사업 자격을 판정한 뒤([[#UC-S5]]) 리포트를 조립한다([[#UC-S3]]).
3. 창구 직원이 리포트를 고객과 함께 본다.
4. 고객이 근거를 묻는 보정 항목을 창구 직원이 선택한다.
5. 시스템이 그 수치의 근거 경로를 펼친다([[#UC-S4]]).
6. 창구 직원이 예산의 위치와 개선 시나리오를 고객과 검토한다. 예산 위치는 평가 대상 시도 동종 창업비용 분포에서 어디쯤인지일 뿐 적정·부적정 판정이 아니라는 점, 창업비용 기준표가 생존 사업체의 응답에 기반한 통계라는 점, 후보 위치가 임대 매물이 아니라는 점을 함께 짚는다.
7. 고객이 대안을 누가 어떻게 골랐는지 물으면, 창구 직원이 대안 옆의 에이전트 실행 기록을 펼쳐 보여준다([[#UC-S11]]).
8. 창구 직원이 지원사업 판정을 안내한다. 판정 불가 공고는 무엇이 없어서 판정되지 않았는지 함께 알려주고, 원문 링크를 건넨다.
9. 창구 직원이 리포트를 심사 큐에 등록한다.

**확장**
- **1a. 고객이 이미 발급받은 리포트의 식별번호를 가져왔다**
  - 1a1. 창구 직원이 식별번호로 리포트를 불러온다.
  - 1a2. 2를 건너뛰고 3부터 진행한다.
- **1b. 식별번호에 해당하는 리포트가 없다**
  - 1b1. 시스템이 찾을 수 없다고 알린다. 1로 돌아간다.
- **1c. 고객이 출생연도를 알려주지 않는다**
  - 1c1. 창구 직원이 입력하지 않고 진행한다.
  - 1c2. 8에서 연령 조건이 있는 공고는 판정 불가로 나오므로, 창구 직원이 원문 링크로 기준 연령을 직접 확인하도록 안내한다.
- **5a. 같은 리포트에서 같은 수치를 다시 선택한다**
  - 5a1. 시스템이 같은 경로를 내놓는다([[#UC-S4]] 확장 1a).
- **7a. 리포트에 실행 기록이 없다 (시연 범위 밖 조합)**
  - 7a1. 시스템이 에이전트 서술 없이 결정론 대안만 담긴 리포트라고 표시한다([[#UC-S11]] 확장 1a).
  - 7a2. 창구 직원이 대안은 결정론 계산의 상승폭 순위로 골라졌다고 안내한다.
- **7b. 리포트가 참조한 적재 릴리스가 에이전트가 서술만 맡은 릴리스다**
  - 7b1. 시스템이 대안 선택은 결정론 순위를 따랐고 에이전트는 서술만 맡았다고 표시한다([[#UC-S2]] 확장 2a, [[#UC-S11]] 확장 4a).
  - 7b2. 창구 직원이 대안 순서는 결정론 계산으로 정해졌고 AI 에이전트는 이유 서술만 썼다고 안내한다.
- **9a. 고객이 신청하지 않기로 한다**
  - 9a1. 창구 직원이 큐에 등록하지 않고 식별번호만 고객에게 안내한다. 유스케이스 종료.

**기본 흐름**
1. 심사역이 심사 큐를 열고 리스크 등급이나 접수일로 정렬한다.
2. 심사역이 리포트를 연다.
3. 시스템이 리포트의 원본 여부를 검증해 결과를 리포트 상단에 표시한다([[#UC-S7]]).
4. 심사역이 생존 전망과 업종 기준선·경쟁 밀도 보정·지역 보정의 분해를 확인한다.
5. 심사역이 보정 수치를 선택하고, 시스템이 근거 경로를 펼친다([[#UC-S4]]).
6. 심사역이 개선 시나리오의 에이전트 실행 기록을 펼치고, 리포트가 참조한 적재 릴리스의 결정론 대비 일치율·반복 안정성과 에이전트가 서술만 맡은 릴리스인지를 확인한다([[#UC-S11]]).
7. 심사역이 원천 기준월, 생존율 산출에 쓴 과거 분기, 출처 표기를 확인한다. 출처 표기에는 창업비용 기준표의 원천 통계명·기준연도, 공고 원문의 공공누리 제3유형 출처표시, 적재 단계에서 OpenAI API를 썼다는 사실과 이용약관·사용정책 준수 사항이 담겨 있다.
8. 심사역이 한계 고지를 확인한다. 상관이지 인과가 아니라는 점, 업력이 데이터 최초 관측 시점 기준이라는 점, 대안 서술은 AI 에이전트가 썼고 수치는 결정론 계산값이라는 점, 창업비용 기준표가 생존 사업체의 응답에 기반한 통계라는 점, 경쟁 밀도가 행정동 대표점 기준이라는 점과 대표점 산출 방식이 담겨 있다.
9. 심사역이 보증 연계·한도 조정·승인 중 하나로 판단한다. 판단 기록은 이 시스템의 범위 밖이다.

**확장**
- **3a. 발급 이후 수정됐다고 판정된다**
  - 3a1. 시스템이 경고를 표시한다.
  - 3a2. 심사역이 원본 재발급을 요청한다. 유스케이스 종료.
- **3b. 검증 불가로 판정된다 (검증 해시 없음·원장 기록 없음)**
  - 3b1. 시스템이 검증 불가 사유를 표시한다. 4부터 그대로 진행하되 심사역은 이 사실을 판단에 반영한다.
- **4a. 코호트가 상위 분류로 폴백된 리포트다**
  - 4a1. 시스템이 폴백 단계와 낮은 신뢰 수준을 눈에 띄게 표시한다.
- **6a. 리포트에 실행 기록이 없다 (시연 범위 밖 조합)**
  - 6a1. 시스템이 에이전트 해석 없이 결정론 대안만 담긴 리포트라고 표시한다([[#UC-S11]] 확장 1a). 7부터 그대로 진행한다.
- **6b. 리포트가 참조한 적재 릴리스가 에이전트가 서술만 맡은 릴리스다**
  - 6b1. 시스템이 대안 선택은 결정론 순위를 따랐다고 표시한다([[#UC-S11]] 확장 4a). 심사역은 대안 선택에 에이전트 판단이 들어가지 않았다는 사실을 감안한다.

**기본 흐름**
1. 운영 담당자가 설정에서 지역 식별자를 대상 시도로 바꾼다.
2. 시스템이 대상 시도의 스냅샷을 적재하고 인접 분기 연속성을 검증한다([[#UC-S8]]).
3. 시스템이 대상 시도의 창업비용 기준표를 적재한다([[#UC-S12]]).
4. 운영 담당자가 대상 시도에 대해 [[#UC-H5]]를 수행한다. 스냅샷과 기준표는 2·3에서 적재했으므로 [[#UC-H5]] 확장 1a에 따라 공고 목록 적재와 조건 구조화부터 진행한다. 공고 조건 구조화와 대상 시도 조합의 적재 시점 에이전트 실행은 이 흐름을 거쳐야만 적재 릴리스에 들어간다.
5. 대상 시도의 적재 릴리스가 활성화되면, 새 릴리스를 참조하게 하는 전환과 함께 평가 대상 지역이 대상 시도로 한 번에 바뀐다([[#UC-H5]] 10). 기존 지역의 입력이 대상 시도의 릴리스를 참조하는 틈이 생기지 않는다.
6. 운영 담당자가 대상 시도 데이터로 [[#UC-H1]]을 한 번 수행해 동작을 확인한다.

**확장**
- **1a. 대상 시도에 행정구역 편입·분리 이력이 있다**
  - 1a1. 운영 담당자가 분리 집계할 지역과 편입 시점을 설정에 함께 지정한다.
- **2a. 2·3의 적재가 실패한다**
  - 2a1. 시스템이 실패 원인을 알리고 4로 넘어가지 않는다. 평가는 기존 지역으로 계속된다. 유스케이스 종료.
- **3a. 대상 시도의 일부 업종에 창업비용 기준값이 없다**
  - 3a1. 시스템이 [[#UC-S12]] 확장 4a에 따라 빈 칸으로 기록하고 진행한다. 그 업종으로 바꾸는 대안은 대상 시도의 리포트에 나오지 않는다.
- **4a. [[#UC-H5]]가 적재 릴리스를 활성화하지 못한다**
  - 4a1. 시스템이 5를 수행하지 않는다. 평가는 기존 지역과 이전 적재 릴리스로 계속된다. 유스케이스 종료.

1. 운영 담당자가 이번 적재의 OpenAI 비용 한도를 정하고 새 데이터 적재를 시작한다.
2. 시스템이 분기 스냅샷을 적재하고 인접 분기 사이 상가업소번호 연속성을 검증한다([[#UC-S8]]).
3. 시스템이 소상공인실태조사 창업비용으로 창업비용 기준표를 적재하고 출처를 기록한다([[#UC-S12]]).
4. 시스템이 지원사업 공고 목록을 적재하고, OpenAI API로 공고 조건을 구조화한 뒤 원문 인용을 검증한다([[#UC-S9]]). 사용자 입력은 보내지 않는다.
5. 시스템이 시연 범위 조합마다 적재 시점 에이전트를 실행해 후보의 제시 순위, 대안 근거 경로, 서술을 만든다. 참조 검증에 실패한 결과는 버리고, 실행 기록을 저장한다([[#UC-S10]]).
6. 시스템이 결정론 대비 일치율과 반복 안정성을 측정해 기록한다([[#UC-S10]]).
7. 시스템이 적재 결과를 운영 담당자에게 보여준다. 연속성 검증에서 뺀 구간과 그 구간이 걸린 실측 기준값을 다시 산출해야 한다는 표시, 창업비용 기준값이 없는 칸, 인용 검증에 실패한 조건, 조합별 에이전트 산출물 검증 결과, 일치율과 반복 안정성이 담긴다. 이 가운데 연속성 검증에서 뺀 구간, 기준값이 없는 칸, 인용 검증에 실패한 조건은 기록만 하고 활성화를 막지 않는다.
8. 시스템이 모델 ID·프롬프트 해시·스냅샷 해시로 적재 릴리스 식별자를 만든다.
9. 운영 담당자가 검증 결과를 확인하고 새 적재 릴리스를 활성화한다. 시스템은 스냅샷 적재와 연속성 검증 구간 확정이 끝났고, 시연 범위 조합 전부의 에이전트 산출물이 참조 검증을 통과했을 때만 활성화를 허용한다.
10. 시스템이 이후 발급하는 리포트가 새 적재 릴리스를 참조하게 한다. 이미 발급된 리포트는 발급 때 참조한 적재 릴리스를 그대로 가리킨다. [[#UC-H4]]에서 넘어온 경우에는 이 전환과 평가 대상 지역 전환을 한 번에 한다.
11. 운영 담당자가 [[#UC-H1]]을 한 번 수행해, 리포트에 새 원천 기준월과 적재 릴리스 식별자가 찍혔는지 확인한다.

**확장**
- **1a. [[#UC-H4]]에서 넘어와 대상 시도의 스냅샷과 창업비용 기준표가 이미 적재돼 있다**
  - 1a1. 시스템이 2·3을 건너뛰고 4부터 진행한다. 공고 목록 적재와 조건 구조화는 새 적재 릴리스를 만드는 흐름의 일부라 함께 다시 돈다.
- **1b. 외부 네트워크가 없다**
  - 1b1. 시스템이 적재를 시작하지 않고 그 사실을 알린다. 평가는 이전 적재 릴리스로 계속된다. 유스케이스 종료.
- **2a. 인접 분기 사이 상가업소번호가 끊긴 구간이 있다**
  - 2a1. 시스템이 [[#UC-S8]] 확장 4a에 따라 그 구간을 코호트에서 빼고 적재를 이어간다. 뺀 구간은 7에서 보여준다.
- **2b. 스냅샷 적재가 실패한다**
  - 2b1. [[#UC-S8]]의 확장에 따라 적재가 중단된다. 시스템이 새 릴리스를 만들지 않고 이전 적재 릴리스를 유지한다. 유스케이스 종료.
- **3a. 창업비용 기준표 적재가 실패한다**
  - 3a1. [[#UC-S12]] 확장 1a에 따라 적재가 중단된다. 시스템이 새 릴리스를 만들지 않고 이전 적재 릴리스를 유지한다. 유스케이스 종료.
- **4a. 4~6에서 OpenAI 비용 한도에 도달한다**
  - 4a1. 시스템이 적재를 중단하고 한도에 도달했다고 알린다([[#UC-S9]] 확장 2a, [[#UC-S10]] 확장 3a).
  - 4a2. 새 릴리스를 활성화하지 않고 이전 적재 릴리스를 유지한다. 유스케이스 종료.
- **4b. 지원사업 공고 목록을 받지 못한다**
  - 4b1. [[#UC-S9]] 확장 1a에 따라 구조화가 중단된다. 시스템이 새 릴리스를 만들지 않고 이전 적재 릴리스를 유지한다. 유스케이스 종료.
- **6a. 반복 안정성이 기준에 못 미친다**
  - 6a1. 시스템이 [[#UC-S10]] 확장 7a에 따라 제시 순위를 결정론 순위로 바꾸고, 에이전트는 서술만 맡게 한다.
  - 6a2. 시스템이 이 릴리스를 에이전트가 서술만 맡은 릴리스로 표시하고 7로 간다. 9의 활성화 조건을 채우면 활성화할 수 있다.
- **9a. 참조 검증을 통과하지 못해 결과가 버려진 조합이 있다**
  - 9a1. 시스템이 활성화를 막고 막힌 조합을 알린다.
  - 9a2. 이전 적재 릴리스가 계속 쓰인다. 유스케이스 종료.

**기본 흐름**
1. 시스템이 과거 분기 스냅샷에서 입력 업종 소분류의 신규 진입 점포를 고른다. 진입 시점은 상가업소번호의 7~12번째 자리인 최초 수집 연월로 판정한다. 인접 분기 연속성 검증을 통과한 구간의 분기만 쓴다([[#UC-S8]]).
2. 시스템이 그 점포들이 중간 분기 스냅샷과 현재 스냅샷에 남아 있는지 상가업소번호로 대조해 업종 기준선 생존율을 낸다.
3. 시스템이 입력 행정동의 대표점에서 반경 300m 안의 동일 중분류 경쟁 점포 수를 세고, 같은 경쟁 구간에 속했던 코호트의 생존율로 경쟁 밀도 보정값을 낸다. 입력에 좌표가 없으므로 기준점은 행정동 대표점이며, 대표점 기준이라는 사실과 대표점 산출 방식을 결과에 담는다.
4. 시스템이 입력 구·군 코호트의 생존율로 지역 보정값을 낸다.
5. 시스템이 세 값, 각 표본 크기, 두 시점 생존곡선을 반환한다.

**확장**
- **1a. 소분류 표본이 60건 미만이다**
  - 1a1. 시스템이 중분류로, 그래도 부족하면 대분류로 올려 다시 고른다.
  - 1a2. 몇 단계 올렸는지와 낮은 신뢰 수준 표시를 결과에 담는다.
- **1b. 대분류로 올려도 60건 미만이다**
  - 1b1. 시스템이 집계 실패를 반환한다. 호출자는 리포트를 발급하지 않는다.
- **1c. 입력 지역이 군위군이다**
  - 1c1. 시스템이 2023년 7월 편입 이전 스냅샷에는 군위군이 없다는 사실을 결과에 담는다.
  - 1c2. 군위군 코호트를 대구 나머지와 섞지 않고 분리해 집계한다.
- **1d. 입력 조건에 맞는 분기가 연속성 검증에서 뺀 구간에 걸린다**
  - 1d1. 시스템이 그 구간의 분기를 쓰지 않고, 뺀 구간을 결과에 담는다.
  - 1d2. 남은 표본이 60건 미만이면 1a로 간다.
- **2a. 외부 네트워크가 없다**

| 트리거 | [[#UC-S1]]이 끝났다. |
| 패키지 | 평가 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 시스템이 입력 조합(업종×행정동)이 활성 적재 릴리스의 시연 범위 안에 있는지 확인한다.
2. 시스템이 활성 적재 릴리스에 저장된 그 조합의 에이전트 산출물을 조회한다([[#UC-S10]]의 결과). 산출물에는 결정론 도구가 계산한 후보와 후보별 상승폭·표본·신뢰 수준, 에이전트가 매긴 제시 순위, 후보별 대안 근거 경로와 참조 검증을 통과한 서술, 실행 기록 식별자가 담겨 있다.
3. 시스템이 예산을 넘는 후보를 버린다. 업종 변경 후보는 창업비용 기준표에서 바꿀 업종의 평가 대상 시도 창업비용을 입력 예산과 비교해 판단하고, 기준표에 그 업종 값이 없으면 버린다.
4. 시스템이 현재 조건보다 전망이 높은 후보만 남기고, 에이전트가 매긴 제시 순위에서 위에 있는 후보부터 대안으로 담는다.
5. 시스템이 입지 변경 대안마다 반경 내 경쟁 조건을 만족하는 좌표를 후보 위치로 붙이고, 공실·임대료 정보가 없어 임대 가능한 매물인지 알 수 없다는 표시를 함께 붙인다.
6. 시스템이 대안 목록을 반환한다. 대안마다 서술은 AI 에이전트가 썼고 수치는 결정론 계산값이라는 표시, 업종 변경 대안의 예산 판단에 쓴 기준표 출처·기준연도, 실행 기록 식별자가 붙는다.

**확장**
- **1a. 입력 조합이 시연 범위 밖이다**
  - 1a1. 시스템이 2 대신 결정론 도구로 조건 축(업종·입지)을 하나씩 바꾼 후보를 만들고, 후보마다 [[#UC-S1]]과 같은 방식으로 생존 전망을 낸다.
  - 1a2. 시스템이 3~5를 수행하되, 4에서는 상승폭 순으로 담는다. 대안은 에이전트 서술 없이 반환하고, 에이전트 해석과 실행 기록이 없다는 표시를 붙인다.
- **2a. 활성 적재 릴리스가 에이전트가 서술만 맡은 릴리스다**
  - 2a1. 저장된 제시 순위가 결정론 순위(상승폭 순)이므로, 시스템이 4에서 그 순위대로 담고 에이전트가 서술만 맡았다는 표시를 대안과 함께 반환한다.
- **4a. 예산 안에서 전망을 올리는 대안이 2개 미만이다**
  - 4a1. 시스템이 찾은 만큼만 반환하고, 예산 안에서 더 나은 조합이 부족하다는 사실을 함께 반환한다. 예산 제약이 대안 개수보다 우선한다.
- **4b. 현재 조건보다 나은 조합이 없다**

- **5a. 입지 조건을 만족하는 후보 위치가 없다**
  - 5a1. 시스템이 그 입지 변경 대안을 목록에서 뺀다.

- **8b. 앵커링이 실패한다**
  - 8b1. [[#UC-S6]]의 확장 3a에 따라 "검증 해시 없음"으로 표시하고 발급은 진행한다.

| 포함(include) | — |

**기본 흐름**
1. 시스템이 활성 적재 릴리스에서 지원사업 공고 목록과 공고별 구조화 조건을 가져오고, 목록을 적재한 시점을 결과에 담는다. 이 단계에서 외부 AI를 부르지 않는다.
2. 시스템이 신청 마감이 지난 공고를 뺀다.
3. 시스템이 공고마다 원문 인용 검증을 통과한 지원대상 조건만 대조한다. 대조 대상은 입력 조건(업종·지역·출생연도)과, 입력이 아니라 예비창업자라는 전제로 정해지는 창업 전 여부다.
4. 연령 조건이 있는 공고는 시스템이 공고에 적힌 기준 연령(만 34세·만 39세 등)을 출생연도에 그대로 적용해 판정한다.
5. 시스템이 공고마다 판정, 판정 근거가 된 조건 대응과 그 원문 인용, AI가 추출한 조건에 기반한 판정이라는 표시, 원문 링크를 반환한다.

**확장**
- **1a. 외부 네트워크가 없다**
  - 1a1. 시스템이 사전 적재한 공고 목록과 구조화 조건을 그대로 쓰므로 흐름이 달라지지 않는다. 목록을 적재한 시점은 1에서 결과에 담긴다.
- **3a. 연령 조건이 있는데 출생연도가 입력되지 않았다**
  - 3a1. 시스템이 해당 공고를 "판정 불가"로 분류하고, 출생연도가 없어서 판정하지 못했다는 사유를 적는다.
- **3b. 지원대상 조건이 출생연도 외에 입력에 없는 속성을 요구한다 (업력·매출 규모 등)**
  - 3b1. 시스템이 해당 공고를 "판정 불가"로 분류하고, 어떤 속성이 없어서 판정하지 못했는지 적는다.
- **3c. 지원대상 조건이 자연어라 입력 조건과 대응시킬 수 없다**
  - 3c1. 시스템이 "판정 불가"로 분류하고 원문을 확인하라고 안내한다.
- **3d. 공고가 지원대상 조건을 첨부 공고문으로 미룬다**
  - 3d1. 시스템이 해당 공고를 "판정 불가"로 분류하고, 조건이 첨부 공고문에 있어 판정하지 못했다는 사유를 적는다. 판정 불가를 넘는 판정을 내리지 않는다.
  - 3d2. 원문 링크로 첨부 공고문을 확인하라고 안내한다.
- **3e. 공고의 조건 일부가 원문 인용 검증에서 빠졌다 ([[#UC-S9]] 확장 3a)**
  - 3e1. 시스템이 그 공고를 충족으로 판정하지 않는다.
  - 3e2. 검증을 통과한 조건 가운데 미충족이 있으면 미충족으로, 없으면 판정 불가로 분류하고 원문을 확인하라고 안내한다.
- **3f. 공고에 구조화 조건이 하나도 없다 ([[#UC-S9]] 확장 2c)**
  - 3f1. 시스템이 "판정 불가"로 분류하고 원문을 확인하라고 안내한다.

1. 시스템이 상가(상권)정보 API로 대상 지역의 현재 점포 전량을 페이지 단위로 받는다. 대구 기준 1,000건씩 119회다.
2. 시스템이 코호트 비교에 쓸 과거 분기 스냅샷 파일을 받아 대상 지역만 추린다.
3. 시스템이 API 응답 필드와 파일 필드의 대응을 확인한다. 둘은 같은 39개 항목이지만 이름이 다르다(API는 영문 키 `lnoCd`, 파일은 한글 헤더 `지번코드`).

- **3a. 필드 대응이 맞지 않는다 (분기 사이 컬럼 추가·삭제)**
  - 3a1. 시스템이 적재를 중단하고 대응이 깨진 필드를 알린다. 이전 스냅샷을 유지한다.

  - 4a1. 시스템이 끊긴 구간을 코호트에 쓰지 않는 구간으로 표시하고 적재를 이어간다.
  - 4a2. 뺀 구간을 적재 결과에 담아 호출자에게 알린다. 그 구간이 걸린 실측 기준값은 다시 산출해야 한다는 표시를 함께 남긴다.

2. 시스템이 공고마다 사업개요 원문을 OpenAI API로 보내 지원대상 조건(업종·지역·연령 등)을 구조화해 받는다. 조건마다 근거가 된 원문 인용을 함께 받는다. 보내는 것은 공고 원문뿐이고, 요청은 응답 저장을 끈 상태로 보낸다.

- **2b. 사업개요가 지원대상 조건을 첨부 공고문으로 미룬다**
  - 2b1. 시스템이 그 공고에 첨부 참조 표시를 붙여 저장한다. [[#UC-S5]]는 이 공고에 판정 불가를 넘는 판정을 내리지 않는다([[#UC-S5]] 확장 3d).
- **2c. 조건을 하나도 추출하지 못한다**
  - 2c1. 시스템이 그 공고를 구조화 조건이 없는 공고로 저장한다. [[#UC-S5]] 확장 3f에 따라 판정 불가로 분류된다.
- **3a. 인용이 원문에 글자 그대로 없다**
  - 3a1. 시스템이 그 조건을 판정 근거로 저장하지 않고 검증 실패로 기록한다.
  - 3a2. 이 기록은 [[#UC-S5]]가 조건이 빠진 공고를 충족으로 판정하지 않는 데 쓰인다.

1. 시스템이 시연 범위 조합(최근 진입 상위 업종×행정동) 목록에서 조합 하나를 꺼낸다.
2. 시스템의 결정론 도구가 그 조합에서 조건 축(업종·입지)을 하나씩 바꾼 후보를 만들고, 후보마다 [[#UC-S1]]과 같은 방식으로 상승폭·표본·신뢰 수준을 계산한다. 현재 조건보다 전망이 높은 후보만 남긴다. 업종 변경 후보는 대상 시도 창업비용 기준표에 그 업종 값이 없으면 빼고, 값이 있으면 그 값을 후보에 붙여 둔다.
3. 적재 시점 에이전트가 도구를 호출해 지식그래프를 탐색하고, 남은 후보 전체에 제시 순위를 매긴다. 예산은 발급 때 들어오는 사용자 입력이라 에이전트가 알 수 없으므로, 순위는 예산과 무관하게 매기고 예산으로 거르는 일은 발급 때 [[#UC-S2]]가 한다. 에이전트는 후보마다 설명력 있는 대안 근거 경로도 고른다. OpenAI 요청은 응답 저장을 끈 상태로 보낸다.
4. 에이전트가 후보마다 비전문가용 서술을 쓴다. 발급 때 예산으로 걸러진 뒤 어느 후보가 남아도 서술이 있게 하기 위해서다. 서술 속 수치와 그래프 노드는 도구 결과를 참조로만 인용하고, 수치를 직접 쓰지 않는다.
5. 시스템이 서술의 수치·노드 참조가 도구 결과와 모두 맞는지 코드로 확인한다.
6. 시스템이 후보·제시 순위·대안 근거 경로·서술과 실행 기록을 로컬에 저장한다. 실행 기록에는 도구 호출 순서, 호출 인자와 결과의 요약, 참조한 그래프 노드, 모델 ID, 프롬프트 버전, 검증 결과가 담긴다. 대안 근거 경로는 적재 릴리스 안에서 고정되며, [[#UC-S4]]가 펼치는 보정 수치의 결정론 근거 경로와는 별개다.
7. 시스템이 1~6을 모든 조합에 반복한 뒤, 결정론 순위(상승폭 순)의 상위 대안과 에이전트 순위의 상위 대안이 얼마나 같은지(결정론 대비 일치율)를 잰다. 같은 조합에 기본 흐름 3단계를 여러 번 다시 실행해 에이전트 순위의 상위 대안이 얼마나 같게 나오는지(반복 안정성)도 잰다. 반복 횟수와 기준값은 아직 정하지 않았다(5장). 두 값을 적재 릴리스 기록에 남긴다.
8. 시스템이 조합별 검증 결과와 두 측정값을 호출자에게 반환한다.

**확장**
- **3a. OpenAI 비용 한도에 도달한다**
  - 3a1. 시스템이 실행을 중단하고, 중단 시점까지의 실행 기록과 중단 사실을 호출자에게 반환한다([[#UC-H5]] 확장 4a).
- **5a. 참조가 도구 결과와 하나라도 어긋난다**
  - 5a1. 시스템이 그 결과를 버리고 3부터 다시 실행한다.
  - 5a2. 다시 실행해도 어긋나면 그 조합의 결과를 버리고, 검증 실패를 실행 기록에 남긴 채 다음 조합으로 간다.
- **7a. 반복 안정성이 기준에 못 미친다**
  - 7a1. 시스템이 조합마다 제시 순위를 결정론 순위(상승폭 순)로 바꾼다.
  - 7a2. 에이전트가 순위는 매기지 않고 후보마다 대안 근거 경로와 서술만 쓰도록 3~6을 다시 수행한다. 참조 검증은 5와 같다.
  - 7a3. 시스템이 적재 릴리스 기록에 에이전트가 서술만 맡았다고 표시한다. 일치율과 반복 안정성은 순위를 바꾸기 전에 잰 값을 그대로 남긴다.
