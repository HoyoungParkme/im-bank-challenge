# 창업 신용 리포트 엔진 PRD

## 1. 목표

트랙은 [[IMBC-RFQ-001#Q19]]에 따라 [[IMBC-RFQ-001#Q1]]의 6개 중 **③ 소상공인·골목상권 디지털 금융**이며, 그 안에서도 세부 예시 "청년 창업 매칭 및 시드 금융 연결 AI"에 대응한다.

제품을 한 문장으로 정의하면 **아직 열지 않은 가게의 신용을 평가하는 것**이다. 은행이 보는 대상을 사업자에서 사업계획으로 바꾼다. [[IMBC-RFQ-001#Q24]]에 따라 이것을 새로운 기능의 추가가 아니라 은행 고유 업무의 회복으로 규정한다. 담보·보증기관·외부 신용점수가 대신하게 된 심사 판단을, 데이터로 은행 안에 되돌린다.

AI 에이전트는 [[IMBC-RFQ-001#Q27]]에 따라 **온라인 적재 단계**에서 일한다. 에이전트가 지식그래프를 도구로 탐색해 반사실 대안을 고르고 근거를 서술해 저장하면, 리포트 발급 경로는 LLM을 부르지 않고 저장된 결과를 조회한다. [[IMBC-RFQ-001#Q13]]의 강점은 에이전트의 실행 기록을 공개하는 방식으로 드러낸다.

#### G1 사업자가 아니라 사업계획을 평가한다
재무제표·매출 이력·담보가 없는 예비창업자를, 동일 조건 코호트의 실측 생존 이력으로 평가한다.

#### G2 대화가 아니라 심사 산출물을 만든다
근거: [[IMBC-RFQ-001#Q23]]. 출력은 채팅 응답이 아니라 여신 심사에 제출 가능한 리포트 문서 한 장이다.

#### G3 모든 판단에 대구 실측 근거를 붙인다
추정 모델이 아니라 실제 대구 점포의 39개월 생존 이력에서 수치를 끌어온다.

#### G4 영업점 심사 프로세스에 그대로 꽂힌다
근거: [[IMBC-RFQ-001#Q22]]. 사장님 셀프 조회와 창구 직원 상담 도구, 두 진입점을 같은 엔진으로 지원한다.

#### G5 시도코드 교체만으로 전국에 이식된다
원천 데이터가 전국 단위이므로 대구에서 검증한 로직이 타 지역에 그대로 적용된다.

#### G6 에이전트가 무엇을 했는지 감추지 않는다
근거: [[IMBC-RFQ-001#Q27]], [[IMBC-RFQ-001#Q13]]. 대안과 서술을 만든 에이전트의 도구 호출·참조 경로·검증 결과를 누구나 펼쳐볼 수 있게 한다.

| 소상공인365 기능 재현 | 상권분석·경영진단·유동인구·배달 통계는 이미 무료로 제공된다. 겹치는 기능을 만들지 않는다 |

## 3. 요구사항

### 3.1 기능

#### R1 창업 조건 입력

근거: [[IMBC-RFQ-001#Q1]], [[IMBC-RFQ-001#Q23]], [[IMBC-RFQ-001#Q26]], [[IMBC-RFQ-001#Q28]]

업종·예산·희망 지역·면적을 선택형 폼으로 입력받고, [[IMBC-RFQ-001#Q26]]에 따라 출생연도를 선택 입력으로 받는다. 자유 텍스트 대화 입력을 두지 않는다.

입력 항목은 세 목적에 필요한 것으로만 한정한다.

| 목적 | 입력 | 쓰는 곳 |
|---|---|---|
| 코호트 매칭 | 업종, 지역(구·군·행정동) | [[#R2]] |
| 창업비용 기준표 대조 | 예산, 면적 | [[#R3]]의 업종 대안 예산 판단, [[#R4]]의 분포 대비 위치 |
| 지원사업 자격 판정 | 출생연도 | [[#R6]] |

상가(상권)정보 원천에는 창업비용·면적·대표자 연령이 없다. 그래서 예산·면적·출생연도는 코호트를 나누는 데 쓰지 않는다.

- [ ] 업종은 상권업종 대·중·소분류 코드 체계를 그대로 쓴다
- [ ] 지역은 대구 8개 구·군 및 행정동 단위까지 좁힐 수 있다
- [ ] 필수 입력(업종·지역·예산·면적) 완료까지 클릭 5회 이내
- [ ] 출생연도를 입력하지 않아도 평가가 진행된다
- [ ] 예산·면적·출생연도는 코호트 집계에 쓰이지 않는다
- [ ] 대화형 입력창이 화면에 존재하지 않는다

#### R2 코호트 생존 추정

근거: [[IMBC-RFQ-001#Q11]], [[IMBC-RFQ-001#Q18]]

입력 조건과 같은 업종·지역을 가진 과거 진입 코호트를 찾아 실측 생존율을 반환한다. 기준선은 업종이고, 경쟁 밀도와 지역으로 보정한다.

데이터 접근 조건은 [[IMBC-RFQ-001#Q18]]에서 확정됐다. 상가(상권)정보 API의 상세기능 20개가 승인돼 반경·행정동·업종별 조회를 모두 쓸 수 있으나, 개발계정 기준 일 10,000건 트래픽 제한이 있어 조회 시점마다 대구 전량(118,357건, 1,000건씩 119회)을 받는 방식은 성립하지 않는다. 따라서 코호트 집계는 사전 적재한 로컬 스냅샷에서 수행하고, API는 스냅샷 갱신과 개별 지점 조회에만 쓴다. 이 전제는 [[#N4]]와 같은 구조다.

생존 이력은 API만으로 복원되지 않는다. 현재 스냅샷에는 생존 점포만 담기므로 코호트의 원래 크기를 알 수 없고, 분기 스냅샷 파일을 함께 적재해야 분모가 확보된다. 진입 시점은 `bizesId`의 7~12번째 자리에 담긴 최초 수집 연월로 식별한다. 분기 파일은 여러 차례 재가공돼 다시 올라왔으므로, 코호트에 쓰기 전에 인접 분기 사이 상가업소번호가 이어지는지 확인하고 끊긴 구간은 쓰지 않는다.

**경쟁 밀도의 기준점.** 입력 지역은 행정동까지라 좌표가 없다. 반경 300m 경쟁 점포 수는 입력 행정동의 대표점을 기준으로 세고, 대표점 기준이라는 사실을 리포트에 고지한다.

2026-09-16 대구 실측 기준값은 다음과 같다. 2022년 9월~2023년 2월 신규 진입 6,895곳(군위군 제외)의 생존율은 15개월 75.7%, 39개월 52.0%다. 같은 기간 2022년 8월 이전 기존 사업자의 생존율은 67.6%로 15.6%p 높다. 업종 대분류별 39개월 생존율은 음식 44.5%가 최저, 교육 66.3%가 최고로 21.8%p 차이가 난다. 반경 300m 내 동일 중분류 경쟁 점포가 0~4곳이면 54.4%, 20~39곳이면 38.0%다. 구·군별로는 남구 48.2%에서 중구 58.0%까지 분포한다. 이 값들은 분기 연속성 검증 전 수치라 적재 검증 뒤 다시 확인한다.

검증 과정에서 **건물 단위 입주 구성과 행정동 점포 증감률은 유의한 신호가 없어 기각**했다. 건물 내 점포 수 구간별 생존율은 43.0~47.0%, 행정동 증감률 구간별은 43.7~45.5%로 모두 오차 범위였다.

- [ ] 업종 기준선·경쟁 밀도 보정·지역 보정이 각각 분리된 수치로 표시된다
- [ ] 코호트 표본 크기가 함께 표시되고, 표본 60건 미만이면 상위 분류로 폴백한다
- [ ] 15개월·39개월 두 시점의 생존곡선을 반환한다
- [ ] 군위군은 2023년 7월 편입이므로 코호트 집계에서 분리 처리한다
- [ ] 코호트 집계가 로컬 스냅샷에서 수행되어 조회 1건당 API 호출이 10건을 넘지 않는다
- [ ] 코호트에 쓰는 분기 구간은 인접 분기 사이 상가업소번호 연속성 검증을 통과한 구간이다
- [ ] 경쟁 밀도 기준점이 행정동 대표점이라는 사실과 그 산출 방식이 리포트에 표시된다

#### R3 반사실 탐색

근거: [[IMBC-RFQ-001#Q13]], [[IMBC-RFQ-001#Q27]], [[IMBC-RFQ-001#Q28]]

현재 조건에서 무엇을 바꾸면 생존 전망이 얼마나 오르는지 역탐색한다. 이 기능이 단순 통계 조회와 제품을 가르는 지점이다.

**역할 분담.** 온라인 적재 단계에서 결정론 도구가 조건 축(업종·입지)을 바꾼 후보 조합과 각 후보의 상승폭·표본·신뢰 수준을 계산한다. 적재 시점 에이전트는 그 도구들을 호출해 지식그래프를 탐색하고, 후보 중 제시할 대안을 고르고, 설명력 있는 근거 경로를 고르고, 비전문가용 서술을 쓴다. **에이전트는 수치를 직접 쓰지 않는다.** 서술 속 수치와 그래프 노드는 도구 결과를 참조로만 인용하고, 참조가 도구 결과와 하나라도 어긋나면 그 결과를 버린다.

**범위.** 업종×행정동 조합이 많으므로 에이전트는 시연 범위 조합(최근 진입 상위 업종 × 대구 행정동)에 대해서만 미리 돌린다. 범위 밖 조합이 입력되면 에이전트 서술 없이 결정론 도구의 상위 대안을 그대로 제시하고, 에이전트 해석이 없다는 사실을 표시한다.

**예산 제약이 대안 개수보다 우선한다.** 업종을 바꾸는 대안은 [[IMBC-RFQ-001#Q28]]의 창업비용 기준표에서 그 업종의 대구 창업비용을 입력 예산과 비교해 판단한다. 기준표에 해당 업종 값이 없으면 그 업종으로 바꾸는 대안은 제시하지 않는다. 예산 안에서 찾은 대안이 2개가 안 되면 예산을 넘는 대안으로 개수를 채우지 않고, 찾은 만큼만 제시하며 부족하다는 사실을 표시한다. 대안이 부족한 리포트의 비율은 4.3 성공지표로 관리한다.

**후보 위치는 임대 매물이 아니다.** 공실·임대료 데이터가 없으므로, 후보 위치는 반경 내 경쟁 조건을 만족하는 좌표일 뿐 지금 들어갈 수 있는 자리인지는 알 수 없다.

- [ ] 개선 시나리오마다 예상 상승폭을 %p로 표시한다
- [ ] 상승폭·표본·후보 집합은 결정론 도구가 계산하고, 에이전트 서술의 수치·노드 참조가 도구 결과와 어긋나면 그 결과를 쓰지 않는다
- [ ] 시연 범위 밖 조합은 에이전트 서술 없이 결정론 대안을 제시하고 그 사실을 표시한다
- [ ] 입지 변경 시나리오는 경쟁 조건을 만족하는 후보 위치를 함께 반환한다
- [ ] 후보 위치가 임대 가능한 매물이 아니라는 점을 함께 표시한다
- [ ] 업종 변경 대안의 예산 판단에 쓴 창업비용 기준표의 출처·기준연도를 표시한다
- [ ] 예산 제약을 위반하는 대안과 창업비용 기준값이 없는 업종으로의 변경 대안은 제시하지 않는다
- [ ] 예산 안에서 찾은 대안이 2개 미만이면 찾은 만큼만 제시하고 부족하다는 사실을 표시한다

#### R4 창업 신용 리포트 생성

근거: [[IMBC-RFQ-001#Q5]], [[IMBC-RFQ-001#Q28]]

[[#R2]]와 [[#R3]]의 결과를 여신 심사에 제출 가능한 문서 한 장으로 조립한다. 화면에 문서 형태로 렌더링되며 리포트 식별번호를 가진다.

[[#R2]]가 로컬 스냅샷에서 집계하므로 리포트에 찍힐 수 있는 날짜가 둘로 갈린다. 원천 데이터의 기준월과, 그 데이터를 로컬에 적재한 날이다. 심사역이 판단 근거의 시점을 따질 때 의미 있는 것은 원천 기준월이므로 그것을 기준일로 표기한다. 생존율은 진입 시점 분기 파일과 현재 스냅샷의 비교로 나오므로, 비교에 쓴 과거 분기도 함께 적는다.

**예산의 위치.** 입력 예산이 대구 동종 업종 창업비용 분포에서 어디쯤인지를 보여준다. 적정·부적정 판정 문구는 쓰지 않고, 기준표의 출처·기준연도·표본 한계를 함께 적는다. 대구·해당 업종 단위 값이 없어 상위 단위(전국 또는 상위 업종)로 올려 쓴 경우 그 사실을 표시한다.

- [ ] 생존 전망, 근거 분해, 권장 여신 한도, 권장 상환 구조, 리스크 등급, 개선 시나리오를 포함한다
- [ ] 권장 한도·금리는 가상 산식임을 문서 내에 명시한다
- [ ] 데이터 기준일은 로컬 적재일이 아니라 원천 기준월로 표기한다
- [ ] 생존율 산출에 쓴 과거 분기 시점을 기준일과 함께 표기한다
- [ ] 예산이 대구 동종 업종 창업비용 분포에서 차지하는 위치를 출처·기준연도·표본 한계와 함께 표시하고, 적정·부적정 판정 문구는 쓰지 않는다
- [ ] 데이터 출처를 문서 하단에 표기한다
- [ ] 리포트 식별번호가 발급된다

#### R5 근거 경로 제시

근거: [[IMBC-RFQ-001#Q13]]

리포트의 각 수치가 어떤 데이터 경로를 거쳐 도출됐는지 펼쳐볼 수 있다. 점포·건물·지번·행정동·업종 계층을 잇는 그래프 경로로 표현한다.

- [ ] 각 보정 수치를 클릭하면 근거 경로가 펼쳐진다
- [ ] 경로의 각 노드는 원천 데이터 필드에 대응한다
- [ ] 경로는 결정론적이며 같은 입력에 같은 경로가 나온다

#### R6 지원사업 매칭

근거: [[IMBC-RFQ-001#Q11]], [[IMBC-RFQ-001#Q26]], [[IMBC-RFQ-001#Q27]], [[IMBC-RFQ-001#Q29]]

기업마당 지원사업 공고의 지원대상 조건과 입력 조건을 대조해 신청 가능한 사업을 제시한다. 자격 판정 근거를 함께 제시하는 것이 핵심이며, 목록 나열이 아니다.

공고의 자격 조건은 사업개요 자연어에 흩어져 있다. 온라인 적재 단계에서 OpenAI API로 조건을 구조화하고, 추출한 조건마다 원문 인용을 붙여 그 인용이 원문에 글자 그대로 있는지 코드로 확인한다. 리포트 발급 경로는 저장된 구조로 규칙 판정만 한다.

판정 결과는 **충족·미충족·판정 불가** 셋 중 하나다. 연령 조건은 [[#R1]]의 출생연도로 판정하며, 청년 기준 연령이 공고마다 만 34세·만 39세 등으로 다르므로 공고에 적힌 기준을 그대로 적용한다. 출생연도가 입력되지 않았거나, 조건이 입력에 없는 속성을 요구하거나, 자연어 조건을 입력과 대응시킬 수 없거나, 공고가 조건을 첨부 공고문으로 미루면 판정 불가로 분류한다. 판정할 수 없는 공고를 충족으로 추정하지 않는다.

- [ ] 각 공고를 충족·미충족·판정 불가 중 하나로 분류하고 그 근거를 표시한다
- [ ] 연령 조건은 출생연도와 공고에 적힌 기준 연령으로 판정한다
- [ ] 출생연도가 없을 때 연령 조건이 있는 공고는 판정 불가로 분류하고, 출생연도가 없어서라는 사유를 적는다
- [ ] 판정 근거에 쓴 조건은 원문 인용 검증을 통과한 것뿐이며, AI가 추출한 조건에 기반한 판정이라는 표시를 붙인다
- [ ] 조건을 첨부 공고문으로 미루는 공고는 판정 불가를 넘는 판정을 내리지 않는다
- [ ] 신청 마감이 지난 공고는 제외한다
- [ ] 공고 원문 링크를 제공한다

#### R7 심사역 큐

근거: [[IMBC-RFQ-001#Q7]], [[IMBC-RFQ-001#Q22]]

생성된 리포트가 영업점 심사역 화면의 큐에 쌓인다. 심사역은 근거 경로를 펼쳐 검토한다. 사내 대회 평가축이던 "영업점과 고객 접점 활용 가능성"에 대응하며, 주최사가 실제로 이식할 수 있는 형태를 보이는 것이 목적이다.

- [ ] 리포트 목록을 리스크 등급·접수일로 정렬해 볼 수 있다
- [ ] 개별 리포트에서 [[#R5]]의 근거 경로에 접근할 수 있다
- [ ] 프로토타입에서는 단일 화면 목업으로 구현한다

#### R8 근거 앵커링

근거: [[IMBC-RFQ-001#Q20]], [[IMBC-RFQ-001#Q27]]

리포트 생성 시점의 입력 스냅샷·근거 경로·모델 버전·출력을 해시해 머클루트로 앵커링한다. 발급자와 검증자가 다르고 신청자에게 유리하게 수정할 유인이 있는 구조이므로, 제3자 검증이 성립한다.

리포트 발급 경로에는 LLM이 없으므로 '모델 버전'은 리포트가 참조한 **적재 릴리스**를 뜻한다. 적재 릴리스는 에이전트와 조건 추출에 쓴 모델 ID·프롬프트 해시·스냅샷 해시로 식별한다.

[[IMBC-RFQ-001#Q20]]이 정한 대로 구현 우선순위는 3순위다. [[#R2]]·[[#R3]]의 품질을 해치면 즉시 제외한다.

- [ ] 리포트 하단에 검증 해시가 표시된다
- [ ] 해시로 앵커 시점을 조회하는 검증 화면이 있다
- [ ] 모델 버전 잎은 리포트가 참조한 적재 릴리스 식별자다
- [ ] 로컬 EVM에서 동작하며 메인넷 배포는 하지 않는다

#### R9 에이전트 실행 기록

근거: [[IMBC-RFQ-001#Q13]], [[IMBC-RFQ-001#Q27]], [[IMBC-RFQ-001#Q23]]

리포트의 대안과 근거 서술을 만든 에이전트의 실행 기록을 펼쳐볼 수 있다. 기록에는 에이전트가 부른 도구의 순서, 호출 인자와 결과의 요약, 참조한 그래프 노드, 사용한 모델 ID와 프롬프트 버전, 검증 통과 여부가 담긴다.

에이전트가 결정론 계산 위에 실제로 무엇을 더했는지도 숨기지 않는다. 적재 릴리스마다 결정론 상위 대안과 에이전트가 고른 대안의 일치율, 같은 조합을 반복 실행했을 때 고른 대안의 안정성을 측정해 기록한다. 안정성이 기준에 못 미치면 대안 선택은 결정론 순위를 따르고, 에이전트는 서술만 맡는다고 표시한다.

- [ ] 리포트 화면과 심사역 화면에서 해당 리포트의 에이전트 실행 기록을 펼칠 수 있다
- [ ] 실행 기록은 네트워크 없이 조회된다
- [ ] 실행 기록에 도구 호출 순서, 참조 그래프 노드, 모델 ID, 프롬프트 버전, 검증 결과가 보인다
- [ ] 적재 릴리스의 결정론 대비 일치율과 반복 안정성이 표시된다
- [ ] 안정성이 기준 미달인 릴리스는 에이전트가 서술만 맡았다고 표시된다
- [ ] 에이전트 서술 없이 결정론 대안만 나간 리포트는 실행 기록이 없다고 표시된다

### 3.2 비기능

#### N1 응답 시간

폼 제출부터 리포트 렌더링까지의 시간. 발표 시연에서 정적이 흐르면 안 된다.

- [ ] 리포트 생성 10초 이내
- [ ] 10초를 넘기면 진행 단계를 화면에 표시한다

#### N2 데이터 출처 표기

근거: [[IMBC-RFQ-001#Q10]], [[IMBC-RFQ-001#Q29]], [[IMBC-RFQ-001#Q30]]

- [ ] 모든 수치에 원천과 기준일이 따라붙는다
- [ ] 외부 AI 도구·라이브러리의 라이선스를 제출물에 명시한다
- [ ] OpenAI API를 적재 단계에서 사용했다는 사실과 이용약관·사용정책 준수 사항을 제출물과 리포트에 밝힌다
- [ ] 기업마당 공고 원문에는 공공누리 제3유형 출처표시를 붙인다
- [ ] 창업비용 기준표의 원천 통계명·기준연도·출처를 표시한다

#### N3 한계 고지

- [ ] 상관이지 인과가 아님을 리포트에 명시한다
- [ ] 업력은 개업일이 아니라 데이터 최초 관측 시점 기준임을 명시한다
- [ ] 코호트 표본이 작은 경우 신뢰 수준을 낮게 표시한다
- [ ] 대안 서술은 AI 에이전트가 썼고 수치는 결정론 계산값이라는 점을 표시한다
- [ ] 창업비용 기준표가 생존 사업체의 응답에 기반한 통계라는 한계를 고지한다
- [ ] 경쟁 밀도가 행정동 대표점 기준이라는 한계를 고지한다

#### N4 오프라인 동작

본선 발표장 네트워크를 신뢰할 수 없다. 외부 API 호출이 실패해도 시연이 중단되면 안 된다. [[IMBC-RFQ-001#Q18]]의 일 10,000건 트래픽 제한 때문에도 로컬 스냅샷이 기본 경로여야 한다.

리포트 발급에 필요한 외부 산출물은 모두 로컬에 둔다. 상가 스냅샷은 [[#R2]]의 코호트 집계에, 지원사업 공고 목록과 구조화 조건은 [[#R6]]의 자격 판정에, 에이전트 산출물과 실행 기록은 [[#R3]]·[[#R9]]에, 창업비용 기준표는 [[#R3]]·[[#R4]]에 쓰인다. 공고는 신청 기간이 있어 시점이 중요하므로, 적재한 목록으로 판정할 때는 그 목록을 언제 적재했는지 함께 보여준다.

- [ ] 대구 전량 스냅샷을 로컬에 캐시해 API 없이 동작한다
- [ ] 지원사업 공고 목록을 사전 적재해, 네트워크가 없을 때 그 목록으로 판정한다
- [ ] 적재한 공고 목록으로 판정한 결과에는 목록 적재 시점을 표시한다
- [ ] 에이전트 산출물·실행 기록·창업비용 기준표를 로컬에 두고 네트워크 없이 조회한다
- [ ] 네트워크 없이 전체 시연 경로가 완주된다

#### N5 지역 확장성

- [ ] 지역 식별자를 설정값으로 분리해 코드 수정 없이 타 시도로 전환된다

#### N6 외부 LLM으로 보내는 데이터 제한

근거: [[IMBC-RFQ-001#Q29]], [[IMBC-RFQ-001#Q10]]

OpenAI API는 적재 단계에서만 부르고, 보내는 데이터는 공개 원천(상가 데이터, 지식그래프, 공고 원문)과 그 결정론 계산 결과로 한정한다.

- [ ] 예비창업자·창구에서 입력한 값(출생연도 포함)은 OpenAI로 전송되지 않는다
- [ ] 리포트 발급 경로에서 OpenAI API를 호출하는 코드가 없다
- [ ] API 요청은 응답 저장을 끈 상태로 보낸다
- [ ] OpenAI API 키는 저장소·제출물·로그에 남지 않는다

## 6. 미결사항

- [ ] 권장 여신 한도·금리의 가상 산식을 어떻게 설계할지 — 생존율에서 한도로 가는 변환 규칙이 미정
- [ ] 리스크 등급 구간(A~D 등) 정의 미정
- [ ] `bizesId` 마커가 최초 수집 시점이라는 해석을 공식 활용가이드로 확인해야 함
- [ ] 분기 연속성 검증 결과 — 재가공 경계(예: 2024년 3분기→4분기)에서 점포번호가 끊기면 2.R2의 실측 기준값을 다시 산출해야 한다
- [ ] 반경 300m 총 점포 수의 U자 패턴은 양 끝 표본이 89건·120건으로 작아 주장으로 쓸 수 없음. 신뢰구간 계산 후 사용 여부 판단
- [ ] 2022년 8월 이전 진입자는 업력이 한 덩어리로 묶여 세분 불가. 더 과거 분기 파일로 분해할지 여부
- [ ] 행정동 대표점 산출 규칙(점포 좌표 중앙값에 가장 가까운 점포 등)
- [ ] 적재 시점 에이전트의 시연 범위 — 최근 진입 상위 업종 수와 조합 목록 확정(상위 10개 업종 기준 점포가 있는 조합 약 1,400개)
- [ ] 에이전트 반복 안정성의 기준값
- [ ] OpenAI 모델 선택 — [[IMBC-RFQ-001#Q29]] 미정 항목. 파일럿에서 비용·정확도를 측정해 참가자가 정한다
- [ ] 창업비용 기준표 확정 — 1순위 후보는 소상공인실태조사 시도·산업중분류별 창업비용. 대구·해당 중분류 셀에 값이 실제로 있는지 확인하고, 없으면 [[IMBC-RFQ-001#Q28]]의 전환 조건을 적용한다
- [ ] 면적 기준값 출처 — 창업비용 통계에 면적이 없다. 공정위 가맹정보를 보조로 쓸지(활용신청 필요, 가맹점 편향), 면적을 참고 입력으로만 둘지
- [ ] [[IMBC-RFQ-001#Q21]]의 폐업·재기 금융을 이번 제출물의 구현 범위에 넣을지, 같은 엔진 위의 설계로만 제시할지
- [ ] 로컬 스냅샷 갱신 주기 — 원천이 분기 갱신이므로 실시간성이 필요한 축이 있는지 확인 필요
- [ ] 지원사업 공고 목록 갱신 주기 — 공고는 상가 스냅샷보다 자주 바뀐다
- [ ] 만 나이 계산 기준일 — 공고일·신청일·평가일 중 무엇으로 셀지
- [ ] iM 캐릭터 사용 여부 — [[IMBC-RFQ-001#Q12]]에 따라 사무국 요청이 필요하다
- [ ] 서비스 명칭 미확정
